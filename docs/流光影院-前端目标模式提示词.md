## 1. 角色、目标与质量底线

你同时是：Windows 桌面产品设计师、UX 工程师、WinUI 3/XAML 架构师、播放与站点适配工程师、发布工程师。

重构后的产品应当具备：

- **内容优先**：影片、频道、播放画面是视觉主体，装饰与面板不争夺注意力。
- **笔记本优先**：以鼠标、键盘、触控板和 14/16 寸笔记本屏幕为核心，不把手机 UI 拉宽，也不照搬电视端海报墙。
- **层级清晰**：用户始终知道自己在哪、在看什么、用的是哪个站点/线路，失败后能做什么。
- **操作直接**：搜索、来源切换、继续观看、切备用源等高频操作不埋进多层菜单。
- **状态可信**：加载、空、部分站点失败、解析中、缓冲、失败、登录等待都有真实且可操作的界面，不伪造成功。
- **看得清**：字号、控件、封面按 §7 的量化标准放大，默认窗口下不需要眯眼。

质量优先级：**数据与凭据安全 > 播放与核心功能正确性 > 任务效率与可用性 > 视觉表现 > 装饰效果**。

## 3. 目标模式执行流程

### 阶段 A：建立真实基线（1–2 轮）

1. 读 `src/TV/`（Views / ViewModels / Services / Models）与 `engine/`，跑一次 Release 构建确认基线可编译（命令见 §12.1）。

4. 建立站点验证表与播放失败复现记录，作为后续对照。

### 阶段 B：重新设计而不是描摹

1. 先产出新应用地图、导航模型、核心任务流、各页线框与状态矩阵，**然后直接实施**，不停留在汇报。

3. 删除重复入口、无效层级、只为填满页面的卡片与无意义说明；所有主控件必须有真实动作。

### 阶段 C：设计系统与应用壳

先落地主题资源、字阶行高、间距网格、控件尺寸、图标、按钮、菜单、对话框、通知、加载/空/错误状态、虚拟化容器与响应式规则，再垂直重构页面。**先做 §7 的尺寸系统，再做页面**，否则会反复返工。

### 阶段 D：功能修复与联调

按「点播/搜索/详情/播放器」「直播」「投屏」「媒体库」「设置/网盘/网络」「安装升级」分批完成；每批都要构建、运行、验证，不允许一次性改完才首次运行。

## 4. 信息架构与应用壳

### 4.1 导航

- 重做主导航，不用截图里那列含义不明的纯图标。一级入口至少覆盖 **点播、直播、媒体库、投屏**；**搜索**作为全局任务独立呈现；**设置**与内容导航分层。
- 宽窗用「图标 + 明确标签」，窄窗可折叠为紧凑模式，折叠后仍有可访问名称与工具提示；当前项选中态必须清晰，不能只靠微弱颜色差异。
- 页面级返回只出现在搜索、详情、播放器等下钻场景；一级主页不显示无意义返回键。支持 `Alt+Left`、键盘焦点与可预测返回路径。
- 全局区只放跨页面操作；站点、分类、筛选、选集等上下文操作留在页面内。

### 4.2 内容区与窗口

- 默认窗口 = 显示器工作区 **55%** 并居中；用户调整后记住尺寸、位置与最大化状态；按显示器与 DPI 校验恢复结果，不得恢复到屏幕外或小于可用尺寸（1.1.9 已实现，重构时保持）。
- 内容流式宽度 + 可读性上限（正文段落 `MaxWidth` 720–860），既不允许机械居中留巨大空白，也不允许固定宽度导致右偏/裁切。
- 窗口缩放时优先重排、折叠次要区域、调整列数，不允许简单缩小字体；页面根布局禁止用写死 `Margin` 补偿错位。
- 标题栏、导航与内容区视觉一体，保留标准窗口控制、最大化、贴靠与托盘行为。

## 5. 各页面重构要求

以下描述的是**任务结构与能力要求**，不是要求恢复截图布局；用合理的 WinUI 布局自行完成高质量设计。

### 5.1 点播与内容浏览

- 推荐、分类、站点、跨站、筛选、接口状态组织成明确的内容浏览体系，避免「横幅 + 标签 + 多个浮动控件 + 海报墙」的简单堆叠。
- 首屏优先展示可消费内容；焦点推荐区不得与下方海报重复占位，数据不足时收起而不是显示空横幅。
- 海报网格虚拟化、自适应列数，统一比例、标题行数、来源标识、占位与失败回退。**封面明显放大**（见 §7.4），悬停揭示关键操作但键盘/触控板同样可用。
- 当前接口、当前站点、跨站状态、筛选条件与结果状态清晰可辨；内置接口可刷新、可切备用源；导入接口可删除。
- 切换来源/筛选时保留合理滚动位置；新请求取消旧请求，禁止慢响应覆盖新页面。
- 推荐失败展示可操作错误，不用空白页或永久骨架屏代替。
- 1.1.9 的吸顶筛选栏与「回到顶部」保留，但要在新视觉系统下重画：吸顶态与页面切换不能有跳变。

### 5.2 独立搜索页

- 搜索有独立页面与完整状态（1.1.9 已拆页）。**输入不自动搜索**，只在 Enter 或点「搜索」后提交；新提交取消上一搜索；清空输入不误发请求。
- 未搜索时展示搜索历史（可单条删除、可清空）；搜索中显示关键词与分站进度；结果区分「无结果 / 加载中 / 失败可重试」。
- 1.1.9 的形态：左侧站点列表（含每站结果数/状态）+ 右侧复用点播瀑布流；选站点**只过滤结果**、仍然并发搜索全部站点。保留该行为（它让用户看到每站进度），但要让「全部站点」的聚合视图与单站视图都清楚。
- 各站结果独立到达、可独立重试，单站失败不阻塞其他结果；返回时保留关键词、选中站点、滚动位置与已加载结果。
- 待补：结果按影片聚合去重（同名不同片不得误合）；搜索历史条目可再次点击直接搜索。

### 5.3 聚合详情页

- 重建「影片信息—主操作—来源/线路—选集—相关内容」层级，不沿用旧详情页结构。
- 片名、年份、类型、地区、简介、海报按重要度排布；主操作「播放/继续观看」最突出，收藏、下载、投屏为次级。
- 汇总所有站点来源并显示可用状态（1.1.9 已在 `DetailPage.xaml` 显示各分享入口状态），支持手动切来源与线路；设置里提供自动切换策略。切来源后正确刷新线路、集数、当前选择与进度，不串用旧来源数据。
- 大量集数用可搜索、可定位当前集、可虚拟化的选集布局，不生成一长排难浏览的按钮。
- 收藏、下载、投屏即时反馈；返回后保留浏览上下文。

### 5.4 播放器

- 与浏览页有明确模式差异；进入播放停止无意义背景动画，控制层自动隐藏，鼠标移动/键盘/触摸可唤醒。
- 控制层按任务分组：播放与进度、集数与倍速、音量、画质、音轨、字幕、弹幕、投屏、画中画、全屏；低频设置进入有层级的弹出面板，不把所有图标排成一排。
- 完整实现加载、起播、暂停、缓冲、seek、切集、切线路、结束、失败、退出状态；关闭窗口、切换视频、退出播放器时取消请求、保存进度、安全释放解码资源。
- 支持清晰度与真实分辨率变体、独立/内嵌音轨与字幕；切画质尽量恢复同名音轨与字幕；支持站点与网盘同目录字幕。
- 支持站点/接口在线弹幕；仅在弹幕开启后展示字号、颜色、屏蔽词设置；内置基础屏蔽规则可关闭，用户规则可编辑并持久化。
- 深度优化起播、预取、缓冲、硬解与退出速度；HDR/帧彩视听、杜比视界按真实硬件检测，设备或片源不支持时明确降级，不得用 SDR 冒充通过。
- 键盘至少覆盖播放/暂停、seek、音量、全屏、返回、字幕/弹幕开关，焦点态清晰可见。

### 5.5 直播

- 重做「直播源—分组—频道—播放」关系，不照搬旧版三个等高大卡片。
- 直播源可切换与刷新，内置与导入源不混淆；频道搜索、分组、当前频道、收藏与播放状态形成连续路径。
- 频道重复从数据模型处理：同频道聚合多个真实线路并显示清晰度，而不是 UI `Distinct` 后丢线路，也不能显示重复项。
- 列表与播放区自适应，窄窗转单任务视图并保留返回路径；支持虚拟化、平滑滚动与当前频道定位。
- 加载、无频道、缓冲、线路失败、全部不可用各有独立状态与重试/切换动作。

### 5.6 投屏

- 重做为「接收状态 + 设备/会话 + 当前播放」的任务中心，修掉旧版整页偏移与空旷失衡。
- 未开启、启动中、等待投屏、发现设备、等待确认、接收中、播放中、失败、已停止都有明确视觉状态；主按钮随状态变化；离开页面与停止接收时按现有规则关闭服务并清理临时文件。
- 手机视频 App 主要把电脑当电视设备，接收端必须按电视投屏协议（DLNA/UPnP）实现发现、描述、控制与媒体传输，不能用 Windows「投影到此电脑」代替。
- 支持开始、暂停、进度、停止与状态回传；扫码选本地视频流程保持可用（1.1.9 已修好本地文件播放）；实体设备结果单独记录，AirPlay 未实现就如实标未完成。
- 「播放器投送到外部设备」与「电脑接收手机视频」是两个任务，入口与状态不得混淆。

### 5.7 媒体库、历史、收藏与下载

- 「继续观看 / 收藏 / 下载」重做为有内容密度的媒体工作区，不再是一条记录漂在巨大空白页里。
- 支持按片名、站点、集数筛选，合理排序，网格/列表切换与批量管理；继续观看显示进度、当前集、来源与看完状态，点击直接续播。
- 收藏与历史跨站点展示；站点失效不清空记录；重匹配失败保留原始信息。
- 下载显示排队、进行中、暂停、失败、完成、文件缺失，可打开文件、定位目录、重试、取消；HLS 下载保持播放列表与分片目录完整。
- 标签页、筛选、排序、滚动位置离开再进恢复；删除/清空可确认或撤销；清理缓存不得删收藏、历史与凭据。

### 5.8 设置与网盘

- 放弃一列长 Expander 堆叠，按「片源 / 播放 / 网盘 / 网络 / 外观与内容 / 存储 / 关于」建立可导航的设置结构，当前分类清晰，常见设置无需反复展开。
- 对齐的响应式表单：标签、输入、开关、按钮同一基线；宽屏不过度拉长，窄屏自动换行，绝不右偏、裁切或缩成小字。
- 片源支持单仓、多仓、独立 TXT/M3U/JSON 导入、删除、刷新与主备切换；结果区分成功/部分成功/具体失败。
- 播放设置：硬解、自动连播、续播、缓存、默认音量、自动切来源；网络：DNS、网盘加速连接、分块；外观：主题、推荐来源、关闭窗口行为、动效偏好。
- 网盘：阿里、夸克保留扫码与手动凭据；**UC 已是扫码登录（1.1.9）**，保留该入口并补取消、超时、登出、失效重登。

- 存储页展示真实缓存分类与大小；图片、元数据、历史、收藏、全部缓存分别处理，危险操作不得复用一个模糊按钮。

## 6. 视觉系统

### 6.1 设计方向

- 建立属于「流光影院」的新视觉语言，而非截图深色界面加绿色按钮的延续：克制、现代、有影院内容氛围；禁止大面积无意义渐变、玻璃、光晕与背景动画。
- 主题支持深色、浅色、跟随系统；颜色全部走语义化 `ThemeResource`，保证两种主题与系统强调色下都可读。
- 用排版、空间、分组表达层级，减少「每个区域都套一张深色卡片」；只有真正需要边界或抬升的浮层、会话、独立任务才用卡片/阴影。
- 图标统一 Fluent 风格与线宽，禁用 emoji 充当站点或功能图标；陌生操作不能只给图标，必要时用文字标签。

### 6.2 动效

- 服务于空间关系与状态反馈：页面进入/返回、下钻详情、面板展开、来源切换、列表更新、通知、播放器控制层。
- 微交互 100–180ms，面板与页面过渡 180–280ms；长列表不做逐项夸张延迟，不用弹簧乱弹、持续漂浮、炫技视差。
- 海报进入详情可连贯动画，但加载慢或图像未就绪时必须平滑回退，不阻塞操作。
- 尊重系统「减少动画」；播放中停止装饰动画，低性能设备优先保证滚动与播放流畅。

## 7. 尺寸系统：这一轮的核心交付（must）

用户在 1.1.9 之后明确抱怨「字体、排版、控件大小、封面偏小，看着费力」。**把下面这些做成设计 token（`ThemeResource`/资源字典），全站统一引用，禁止各页各写一套数字。**

### 7.1 字阶（单位 px，行高另列）

| 用途 | 字号 | 行高 | 字重 |
| --- | --- | --- | --- |
| 页面主标题 | 30 | 38 | SemiBold |
| 分区标题 | 21 | 28 | SemiBold |
| 卡片/影片标题 | 16 | 22 | SemiBold |
| 正文与控件 | 15 | 22 | Regular |
| 次级说明、按钮副标 | 14 | 20 | Regular |
| 元数据（年份/时长/集数） | 13 | 18 | Regular |

- 正文与常规控件**不得低于 14px**；元数据不得低于 13px，也不得靠低透明度掩盖层级问题。
- 一次性把现有偏小的 12/11px 文案提升到上表；禁止出现 11px 以下可读文本。
- 中文走清晰系统字体回退（`Microsoft YaHei UI` → `Segoe UI Variable`），数字与英文同族对齐。

### 7.2 间距与栅格

- 4px 基础网格；页面外边距：宽窗 32，标准窗 24，窄窗 16。
- 区块间距 24–32，组内间距 12–16，元素内边距 8–12；相关元素靠近、无关元素拉开。
- 表单标签与输入同基线；网格标题、工具栏、页面边缘严格对齐，禁止写死 `Margin` 凑位置。

### 7.3 控件尺寸（命中区域）

- 导航项高 **48**，图标 20–24，标签与图标间距 12。
- 主按钮高 **44**，次按钮高 **40**，最小点击区域不小于 40×40；图标按钮 40×40，图标 20。
- 输入框高 **44**；下拉/菜单项高 **40**，菜单内边距 8/12。
- 列表行高 ≥ 48；卡片内边距 16；`CornerRadius` 统一（卡片 12、按钮 8、输入 8）。
- 所有可交互元素实现 Rest / Hover / Pressed / Disabled / FocusVisible；选中态不能只靠颜色；危险操作与普通操作有明确区分。

### 7.4 海报与网格

- 默认 55% 窗口下海报宽 **≥ 180px**，列间距 16–20，行间距 20–24；宽窗自动增列，最小实用窗不低于 2 列可读。
- 海报统一 2:3，标题最多 2 行 + 元数据 1 行；来源/清晰度标识字号 13。
- 封面加载有骨架占位与失败回退，禁止拉伸变形；悬停揭示播放入口与更多操作。

### 7.5 验收方式

- 在 1366×768、1920×1080、2560×1440 与 100%/125%/150% DPI 下截图对比，重点看：正文是否 ≥14px、按钮是否 ≥40px 高、海报是否 ≥180px 宽、是否有 11px 文本残留。
- 用一次全站「字号/尺寸审计」（grep `FontSize=`、硬编码 `Height=`、`Margin="0,0,` 等）确认没有漏网的局部小字号。

## 8. 响应式、可访问性与现代 Windows 特性

- 在默认 55% 窗口、最小实用窗口、最大化、宽屏四种形态下分别设计，不靠一组固定断点应付。
- 实测 1366×768、1920×1080、2560×1440 与 100%/125%/150% DPI；连续缩放无跳坏、重叠、右偏、横向意外滚动、按钮消失。

- 文本/图标/焦点指示对比度合理；错误、成功、当前选中不只靠红绿区分。
- 保留并完善托盘、快捷方式恢复、全屏、画中画、系统媒体控制、贴靠、深浅色与系统主题切换。

## 9. 站点适配与真实可用性

### 9.1 模块化架构

- 默认 C# 原生 Provider；确有必要才用 Java/WebView2，并记录原因。
- 围绕统一首页/分类/搜索/详情/解析抽象模块；CMS JSON/XML、HTML 列表、网页播放器解析、盘搜、直播等公共实现复用，禁止复制整站代码只改 URL。
- Provider 与 UI 解耦；站点能力差异通过能力与状态模型表达，UI 不为每站堆 `if`。
- 保留合法公开实现与上游许可证；无桌面实现、协议不公开或站点已失效时如实标记，不删除提示冒充支持。

### 9.2 全站点四阶段验收

对每个内置站点逐一执行并记录：

1. **实现存在**：配置能路由到真实 Provider/爬虫实现。
2. **真实内容**：首页/推荐、分类、搜索不是空响应、验证码页、挑战页或错误页。
3. **详情可用**：元数据、来源、线路、选集正确解析。
4. **真实播放**：取得有效媒体地址，进入 Playing，持续播放足够时间并观察缓冲、seek、退出。

分别验证搜索、推荐、详情、播放，不得以「类名存在」或「首页成功」代替整站成功。非网络原因的失败必须修复；站点失效、验证码、外部账号限制要给出日志与复现证据并标外部阻塞。

### 9.3 请求稳定性与风控规避

- 合并重复请求，合理短期缓存、按站并发限制、超时、取消、指数退避与抖动，避免切页或自动重试形成请求风暴。
- 使用与公开访问匹配的必要请求头与来源，不滥发 Head/Range，不重复下载相同分片，不在后台轮询无变化页面。
- 403、412、验证码、Cloudflare 挑战、空响应分别处理；优先合法公开备用入口，不以高频重试、伪造成功或绕过安全机制作为方案。
- 自动切换只针对可恢复错误，避免多站无上限尝试；用户可见当前尝试与最终失败原因。

## 10. 播放、解析与故障处理

- 「播放失败：媒体地址无效或已失效」：区分地址过期、鉴权参数丢失、响应非媒体、跨域/请求头、HLS 清单/分片/密钥、真实源失效；必要时重新解析并自动尝试下一线路。
- 「转码播放失败 (HD4oo) data invalid::[plf_invalid]」：检查转码参数、账号/分享状态、响应内容与原画回退链路，不吞服务端错误；提供重试、切清晰度、切线路。
- 「爬虫响应为空」「片源暂不可用」：查 IPC 请求 ID、实例隔离、站点 key、参数编码、响应格式、超时、异常与空数据映射，Debug 搜索/推荐/播放全链路。
- 网页解析只在需要时创建 WebView2，识别真实媒体类型，支持无扩展名 HLS，只接受合理成功响应；单分片失败不能当作新视频。
- 网盘原画/转码、HLS、MP4/MKV、多音轨、多字幕分别建样本；Range 预取有界、可取消、按源限制请求头并复用分片地址。
- **夸克网盘的已知陷阱（1.1.9 已修，改代码时别破坏）**：每次接口调用都会轮换会话 Cookie（响应头 `Set-Cookie: __puus=...`），CDN 只认最新 `__puus`；必须经 `CloudCookieJar` 吸收并持久化，绝不能拿 DB 里的旧 Cookie 直接回源，否则固定 412。匿名分享请求的 `Set-Cookie` 不得写回登录凭据（否则掉成 guest，`file/sort` 401）。转存记录键用 `AccountKey(__uid)`，不要用整串 Cookie 哈希，否则轮换后重复转存出 `(2)`/`(3)`。
- 任何「自动切换成功」必须确实进入可播放状态，不能只把错误提示隐藏。

### 12.3 UI 自动化的坑

- 控件定位走 `window_control.ps1` 的 UIA 封装：`ui(hwnd, 名称, 动作)`；站点/选项卡这类 `ListViewItem`/`ListBoxItem` 用 `select`，按钮用 `invoke`，开关用 `toggle`，菜单项用 `expand` + `item=True`。动作不匹配只会得到含糊的 `Missing control`。
- `physical_click` 在本会话（SetCursorPos + 断言 cursor 落在 bounds 内）不稳定，优先 `invoke`，必要时 `time.sleep(.8)` 等待页面切换。
- 改 XAML 后同步更新脚本里的控件名；`wait_ui(hwnd, name, timeout)` 模式能显著降低偶发失败。
- 数据根默认 `%LOCALAPPDATA%\TV`（`tv.db`、`diagnostic.log`）；脚本用临时 profile 隔离，需要真实凭据时把真实 `tv.db` 拷到临时 root。

### 12.4 已知环境限制（本机 DSH 沙箱会话）

- **托盘图标加不上**：`Shell_NotifyIcon(NIM_ADD)` 在 .NET 进程返回 FALSE（独立 .NET 控制台同样失败；Python ctypes 版成功）。现象是「最小化不隐藏」。产品侧已优雅降级；回归脚本用 `has_icon(hwnd)` 探测后走降级断言。**不要据此改产品逻辑，也不要标成产品回归。**
- **安装器写不了卸载项**：`RegCreateKeyEx 失败；错误代码 5`（`HKCU\...\Uninstall\{...}_is1`），而 PowerShell 直接写同一路径成功 → 是沙箱对安装器进程的拦截。规避：用 `/DUninstallRegKey=no` 编译 QA 安装包；正式包不受影响。
- **运行中覆盖升级卡住**：Restart Manager 无法关闭沙箱内启动的应用，`DeleteFile 失败；错误代码 5`。需在真实桌面环境重跑 `setup-check/run-window-install.ps1`。
- 需要跨出沙箱执行某条命令时，可用计划任务：`schtasks /create /tn X /tr "..." /sc once /st 23:59 /f` + `schtasks /run /tn X`（用完 `schtasks /delete`）。本机 `cmd //c` 在 MSYS 下会被路径转换破坏，改用 `cmd /c` 并设 `MSYS_NO_PATHCONV=1`。

## 14. 禁止事项

1. 禁止把截图当设计稿临摹，禁止只改颜色、圆角、阴影便称「大规模重构」。
2. 禁止只交付建议、伪代码、孤立 XAML 片段或 ViewModel 骨架；必须落地到当前解决方案并实际构建。
3. 禁止用静态假数据制造漂亮截图；设计时数据不得进入运行链路。
4. 禁止为整齐隐藏失败站点、删异常日志、吞异常、跳过测试、把未验证项标完成。
5. 禁止页面各处硬编码颜色、字号、固定偏移与重复控件模板；公共视觉必须进入资源与组件体系。
6. 禁止大段解释性文字、营销文案、装饰性小字、无意义欢迎页。
7. 禁止「动画全覆盖」式炫技；影响性能、阅读、操作或减少动画偏好的效果必须移除。
8. 禁止以网络原因笼统跳过全部站点，也禁止把外部账号、真实设备、硬件限制伪造成已验证。
9. 禁止清空数据库、收藏、历史、凭据解决升级问题；禁止明文记录 Token/Cookie。
10. 禁止首个可编译版本后停止；必须完成状态补全、视觉走查、功能回归与发布。

## 15. 最终交付与汇报格式
